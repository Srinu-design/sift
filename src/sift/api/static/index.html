Sift

Question answering over your documents that cites the section behind every claim, refuses when the evidence is missing, and proves every retrieval change with a measured eval.

The live demo answers from the PostgreSQL 16–18 manuals. Ingestion runs as jobs on Hopper, my own job queue.

Try it How it works

What it does

  • Cites every claim

    Every sentence of an answer cites a numbered source with its section or page, and code rejects any citation that does not point to a retrieved chunk.

  • Refuses without evidence

    Two gates: a low rerank score refuses before any model call, and the model itself may refuse. Refusal precision and recall are measured.

  • Measured

    A versioned golden set of 141 questions. CI runs the retrieval eval on every pull request and fails the build on a regression.

  • Multi-tenant

    Each customer sees only its own documents: tenant filters plus row-level security in Postgres, with tests for chunks, answers and cache entries.

  • Ingestion on Hopper

    Parse, embed and activate run as Hopper jobs, with retries, a dead-letter queue and replay.

How it works

The query path

  1. Auth and tenancy The tenant comes from the API key, never the request; every transaction is scoped to it, and row-level security is the second layer.
  2. Answer cache Keyed by tenant, collection, index version, strategy, filters, prompt version, model and the normalised question.
  3. Dense and lexical search Dense top 50 (pgvector HNSW) and lexical top 50 (Postgres full-text) run concurrently, with metadata filters inside both.
  4. Fusion Reciprocal-rank fusion with k = 60 merges the two lists.
  5. Rerank A cross-encoder rescores the fused top 30; the top 8 go to the model.
  6. Gate 1 If the best rerank score is below τ = 0.19, Sift refuses without calling the model.
  7. Answer and check The model returns JSON with [S#] markers and short quotes; code checks every id, every quote, and that every sentence cites. One retry, then refusal.
  8. Gate 2 The model may refuse itself. The query is logged with timings per stage, tokens, cost and the gate.

The ingest path

An upload is stored under its SHA-256, so an unchanged file creates nothing and makes no embedding calls. A Hopper parse job splits HTML by sections and PDFs by page (chunks of about 400 tokens, 15% overlap, never across a section or page), embed jobs run per 64 chunks on their own queue, and activate swaps the document's live version atomically.

On the live server the index was restored from the evaluated local database; live uploads are not enabled there.

Reranking is the first real gain: MRR@10 +0.086 [+0.018, +0.163] over naive. Hybrid alone beats lexical but ties naive: it fixes exact identifiers (version-specific hit@5 0.70 → 1.00) but lets two medium ranks beat one first place, which the reranker fixes.

Evaluation

  • Golden set v1: 123 PostgreSQL questions (17% unanswerable), labelled by section, with a frozen dev/test split; v2-sebi: 18 questions with page labels and prompt-injection cases.
  • Retrieval metrics (hit@k, recall@k, MRR@10, bootstrap intervals, paired comparisons) gate every pull request; the gate blocked a deliberately bad one.
  • Answers, refusals, citations and the LLM judge run nightly. The judge's correctness score is not yet trusted (kappa 0.489 against 40 hand labels).
  • Every dated run is on the Eval history tab.

Tenancy and security

  • Tenant filters plus row-level security on a shared index; tests prove tenant B cannot retrieve tenant A's chunks, answers or cache entries.
  • API keys look like sift_live_<prefix>_<secret>; only an HMAC of the secret, with a server-side pepper, is stored.
  • Sources are treated as data: prompt v2 fences them, and all three instructions planted in a tenant-B document were resisted.
  • This page runs under a strict Content-Security-Policy and renders model output as text only.

Operations

  • Answer cache keyed by index version, a query-embedding cache, per-client rate limits and a per-tenant daily spend cap.
  • Prometheus metrics and a Grafana dashboard: p50/p95 per stage, cost per query, cache hit rate, refusals by gate, errors.
  • Load: 0.5 requests/s with p95 under 3 s without the answer cache, 1 request/s with it; the cross-encoder saturates first.
  • Deployed from GitHub Actions; each release must pass a retrieval smoke test or the previous one comes back automatically.

Decisions

  1. Postgres (pgvector + full-text search) instead of a dedicated vector database
  2. Reciprocal-rank fusion with k = 60 instead of weighted score fusion
  3. Rerank the fused top 30 with ms-marco-MiniLM-L6-v2 on CPU
  4. Structure-aware chunking at ~400 tokens with 15% overlap, from the ablation
  5. Embedding model: local bge-small-en-v1.5, not an API model
  6. Ingestion as Hopper http jobs; internal-host allowlist; a queue for embedding
  7. Gold labels at section or page level, never chunk ids
  8. Two-gate refusal, with τ tuned on dev
  9. Retrieval eval on every PR; generation eval nightly
  10. LLM judge, validated against human labels (not yet trusted for correctness)
  11. Answer cache keyed by index_version; no semantic cache
  12. Tenant isolation with filters plus row-level security, on a shared index
