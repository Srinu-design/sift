added is picked up without editing a list.

## Rules

- **Never re-crawl during an eval.** Every number names the files it ran against through
  [`manifest.jsonl`](manifest.jsonl): one line per file with URL, path, SHA-256, version,
  source and fetch time. The manifest is committed; the raw files (`raw/`) are git-ignored.
- A new snapshot is a deliberate act (`make corpus`) and a new manifest, which shows in a diff.
  A golden set is tied to a snapshot: anchors such as `id-1.9.3.69.8` are generated by the docs
  build and can change between minor releases.
- To get the raw files on a fresh clone, run `make corpus`, then check the hashes match the
  manifest (week 5 publishes the snapshot as a release asset so CI downloads exactly these).

## Known biases (for the design doc)

- The LLM already knows PostgreSQL well, so answers are graded on citations and faithfulness,
  not only correctness.
- Pages are near-identical across versions: dense search without the version filter mostly
  returns the right section from the wrong version. That is what the filter is for.
- Reference pages (`sql-*`, `app-*`) have long "Parameters" sections, so a section-level gold
  label there is coarser than on chapter pages.
